tea never reads your password. When macOS asks, that prompt belongs to macOS.

There is no daemon, listener, account, or telemetry. Privileged work is a fixed `/usr/bin/pmset` call. The only network requests are the release check against `api.github.com` (at most daily, and on `tea update`) and the download you ask for; details in [appkit](https://github.com/soundadam/appkit#更新).

## Passwordless helper

The client can install a root-owned helper for this account only:

- `/Library/PrivilegedHelperTools/com.soundadam.tea.helper.<uid>`
- `/etc/sudoers.d/soundadam-tea-<uid>`

That rule covers `disablesleep` `0`/`1`, one tea shutdown, and cancelling that event. Not a shell. Not arbitrary `pmset`.

<Warning>
  Any process running as your user can then perform those operations. Skip this on a shared account.
</Warning>

Updating tea (`tea update` or `brew upgrade`) does not replace the helper. The client offers repair when versions diverge.

Releases are built from the version tag by the repository's release workflow. The executables are ad-hoc signed, not notarized. `tea update` on a downloaded copy checks the archive against the SHA-256 GitHub records for it; the Cask pins the same checksums.

## Report a vulnerability

Use GitHub's **Report a vulnerability** form. Don't file a public issue. Details: [SECURITY.md](https://github.com/soundadam/tea/blob/main/SECURITY.md).
